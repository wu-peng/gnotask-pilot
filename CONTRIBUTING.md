# Contributing to GnoTask Pilot

Thank you for contributing to the first real GnoTask pilot. This repository tracks GnoTask Task `026c3428-1ecd-4498-aa04-562ed00c0b51` and funding commitment [Issue #1](https://github.com/fjwupeng/gnotask-pilot/issues/1).

Keep every contribution focused, reviewable, and backed by public evidence.

## Setup

1. Fork `fjwupeng/gnotask-pilot` into your GitHub account.
2. Clone your fork and enter the repository.
3. Add `https://github.com/fjwupeng/gnotask-pilot.git` as the `upstream` remote.
4. Fetch `upstream/main` before starting work.

This pilot currently has no build dependencies. Documentation changes can be reviewed directly from the pull request.

## Branch workflow

1. Create a descriptive branch from the latest `upstream/main`.
2. Keep commits limited to one useful outcome.
3. Do not commit credentials, wallet secrets, generated files, or unrelated changes.
4. Rebase or update the branch if the upstream default branch changes.

## Pull request

- Open the pull request against `fjwupeng/gnotask-pilot:main`.
- Link Issue #1 and include the GnoTask Task ID.
- Explain what changed and how each acceptance criterion is satisfied.
- Keep maintainer edits enabled.
- Wait for the Contributor guide check to pass before requesting review.

## Evidence

Before submitting delivery in GnoTask, collect:

- the public pull request URL;
- the exact pull request head commit SHA;
- the GitHub Actions check result for that commit; and
- a short summary mapping the changes to the acceptance criteria.

GnoTask independently reads the pull request and CI state from GitHub. Screenshots alone are not accepted as delivery evidence.

## Definition of done

The contribution is complete when the guide is clear, the automated check passes, the Sponsor accepts the evidence, and the pull request is merged.
